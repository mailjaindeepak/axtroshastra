01 — the one rule everything hangs on

Only the content changes. The machine never does.

The design system — format, theme, layout, decoration, the three fixed pages — is frozen. Per person, only the section content and chart-driven values swap in. If you find yourself re-touching CSS, mandalas, or spacing for a new person, stop: that belongs to the machine, not the content.

What swaps vs. what's welded

The renderer only string-replaces name, birth details and computed numbers into the approved body. Everything visual stays byte-for-byte identical.

◆ Welded — identical for everyone

  • Cover page — brand, constellation, title, only the name + birth line change
  • "A Note for You" (page 2) — flower-tile mandala, framed note, only the first name changes
  • "Thank you" (last page) — closing mandala, cross-sell, constellation; only the name changes
  • All CSS — tokens, layout, components
  • The whole decoration system — mandalas, positions, opacity, constellations

● Dynamic — filled per person

  • The name & birth line (cover, note, thank-you)
  • Dimension scores — radar, bars, 2×2 positions
  • Archetype & decision style — which cell is highlighted
  • Phase, timing, life-stage bands — the dated content
  • All the prose inside the content sections
How: the approved mock's CSS / SVG-defs / body become constants in *_assets.py; render_*(payload) does targeted string replacements (e.g. >Rajesh Menon< → the real name). Never hand-write per-person HTML.
02 — the physical format

One section = one page. The page-break is structural.

There is no manual "page break." Each <section class="page"> is a card, and @page{size:430px 830px} makes each card land as exactly one PDF page.

The page-break rule

/* one CSS page == one 430×830 card */
@page{ size:430px 830px; margin:0 }

.page{
  width:min(430px,92vw);
  min-height:min(830px,192vw);
  padding:46px clamp(22px,5.5vw,30px) 50px;
  position:relative;
  overflow:hidden;   /* past the edge = CLIPPED */
  display:flex; flex-direction:column;
  align-items:center; justify-content:center;
}
/* keep gold & tints in print */
*{ -webkit-print-color-adjust:exact;
   print-color-adjust:exact }

The headless-print rule

# production & verification use the SAME engine:
# headless Chrome, not a PDF library
"/Applications/Google Chrome.app/Contents/\
MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-sandbox \
  --print-to-pdf=out.pdf \
  --no-pdf-header-footer \
  "file://REPORT.html"
Gotcha: if your PDF is A4 (595×842pt) you printed the browser/viewer, not the file. Open the downloaded .html directly, or use the headless command above → you get 323 × 623 pt cards.

04 — the design rules

What makes it read "executive," not "astrology PDF."

The manager's brief, encoded: minimal astrology graphics, lots of white space, an intelligence report — not "I bought an astrology PDF."

Alignment

Headers centered on every page (.head, .action, .subtit, .eyebrow). Body prose, lists and legends stay left-aligned. Centered title, left body.

Vertical position

Every page vertically centers its content — equal spacing top and bottom on every card, short pages and full pages alike.

White space is on-brand

One idea per page; a lean card centered with balanced top/bottom margins reads as intentional. If a page is thin, add a legend or callout — never stretch the type.

No coloured left-strip

Boxes have no accent rail. A coloured strip reads as "AI-generated," which lowers trust — removed on purpose across every callout and block.

/* every card centers its content — equal top & bottom */
.page{ justify-content:center }
05 — the McKinsey exhibit format

The signature layout: chart, then a read.

Every data page follows one exhibit grammar — so the middle of the report feels like one consulting deck, not a scrapbook. Order is always the same:

  1. .exlabel — the small gold eyebrow
  2. .action — a claim as headline ("Judgement and structure lead"), not a topic
  3. .subtit — the axes / what's plotted
  4. .exrule — hairline divider
  5. the inline-SVG chart (radar, 2×2, bars, donut, timeline)
  6. .leg — a 2–3 row legend reading the chart
  7. .take — "THE READ": the one-line takeaway
Winner-cell rule for 2×2s: highlight the winning quadrant with a soft gold fill and a bold gold label; put any marker dot below the label — never a ring on top of the text.

06 — the decoration system

Two mandalas. They are not interchangeable.

Both live in report_view.py as data:image/svg+xml URIs. Use the right one in the right place — and never "optimize" them; the full detail is the point.

⚠ Anti-drift rule — this recipe does not contain the real SVGs, on purpose.

The art lives in exactly one place: CareerIntelligence-FINAL.html (mirrored in report_view.py). Identify each by its exact length and copy the whole data:image/svg+xml,… string verbatim. Never redraw, simplify, or approximate — every hand-drawn shape on this page (the icon dots, the page thumbnails below) is schematic illustration only and will drift the look. Pull the exact SVGs:

python3 - <<'PY'

u=sorted(set(re.findall(r"data:image/svg\+xml,[^\"')]+",

08 — the non-negotiable gate

Never ship a build without running this.

Content is persona-driven and must pass two hard filters — Meta-safe (no medical / mental-health words, or the site gets classified Health & Wellness) and no data leak (reuse the design, never Business-Growth's text).

# 1 · structure, leak, meta
grep -c '<section class="page' report.html            # expect page count
grep -ic 'vyapar\|business growth\|rohit\|dear rohit' report.html   # → 0
grep -ioE '\b(calm|stress|anxiety|wellness|mental|medical|pressure|relief|burnout|healing)\b' report.html  # → empty

# 2 · render (production path) & check size
chrome --headless=new --print-to-pdf=out.pdf --no-pdf-header-footer "file://report.html"
python3 -c "import pypdf;r=pypdf.PdfReader('out.pdf');p=r.pages[0];print(len(r.pages),p.mediabox.width,p.mediabox.height)"
# expect: N pages, 323 x 623 pt  (NOT 595x842)

# 3 · overflow — rasterize any changed page & LOOK (nothing clipped at the bottom)
#     split page → 1-page pdf (pypdf) → sips -s format png
Pass = page count right · size 323×623 · leak 0 · meta empty · no page clipped · cross-links (href="#…") intact. And never trust a build agent's "done" — re-run the gate on its actual output.
09 — decisions & corrections log

Every call that shaped the final product.

These are settled — the reasons are baked in so they don't get re-argued or accidentally reverted.

Standalone HTML document, printed directly

Printing the claude.ai viewer gave A4. Fix: the report is a complete <!DOCTYPE html> doc; open it and Cmd+P (or headless print) → correct 323×623 cards.

Reuse the Business-Growth design, never its words

Cloned the note-page frame, medallions and icon set — but every build greps for vyapar / business growth / rohit = 0. Design travels; text does not.

Removed the coloured left-strip from every box

It "represents the report is prepared by AI, which reduces trust." Boxes are now clean fills, no rail.

Keep the full-detail mandala — don't optimize

A simplified/optimized mandala cheapened the look. Full 37K/28K SVGs restored and kept.

The note page uses the flower-of-life tile — not the sunburst

First attempt used the wrong mandala. The reference is the interlocking petal lattice, on the .page.note background at native 224px (copy BG's rule verbatim).

Backgrounds must be visible but never fight text

Decoration was invisibly faint (and a %2523 encoding bug made it render nothing). Raised opacity, fixed encoding, text pinned above at z-index:1.

Mandalas scatter — they don't sit in one fixed corner

A pinned top-left mandala looked mechanical. Now rotated across corners via nth-of-type, with some pages left bare.

Headers horizontally centered; content vertically centered

Exhibit headers were left-aligned — centered them all. Content is centered top-to-bottom with equal margins on every card (final-review preference; an earlier top-align was tried, then reverted).

Auto page numbers in the footer

Added a CSS-counter footer (01, 02…), hidden on the cover — no manual numbering.

Fill the empty pages with real substance

Thin cards got 2–3 row legends / callouts — on-topic, persona-consistent, never filler — to ~85–92% fill.

Fixed the legend two-column bug

A <b> that was a direct flex child split label from text. Wrapped both in one .lt span so each row flows as one line.

Added a closing "Thank you" page + constellations & planets

Career-appropriate cross-sell, Meta-safe copy, centered watermark + constellation — matching the Business-Growth close without its content.

Locked: the three welded pages & the "content-only changes" contract

Cover, note and thank-you are templates; only the name/birth line and computed values ever change per person.

10 — gotchas that cost real time

Don't step on these twice.

1 · Double-encoded # makes a mandala invisible.

%2523 = literal %23 = an invalid colour → the SVG paints nothing (looks like opacity, isn't). Colour must be single-encoded %23b9862e inside a data-URI.

2 · A data-URI in an inline style="" breaks the attribute.

The SVG's own quotes close style=" early, so the background silently never applies. Put mandala/tile backgrounds in a CSS class or <style> block — never inline.

3 · Regex-replacing an SVG by its viewBox can hit the wrong page.

Two charts shared viewBox="0 0 300 275", so a global replace clobbered the radar with the decision matrix. Match by the page's unique heading, or give every chart a unique viewBox.

4 · Overflow is silent.

overflow:hidden deletes anything past the card bottom with no warning. Always rasterize a changed page and confirm the last line clears the edge.

5 · --screenshot is unreliable here; verify by rasterizing the PDF.

Render with --print-to-pdf, split with pypdf, view with sips. That is the trustworthy visual check.
